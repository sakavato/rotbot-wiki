# 교육 키워드와 연결의 공백 검토

[처음으로](README.md) · [전체 지도](robotics_system_overview.md) · [핵심 개념](concepts.md)

이 문서는 필요할 때 확인하는 참조 기록이다. 아래의 공백·심화 항목 전체를 학습하거나 별도 문서로 확장해야 한다는 뜻은 아니다.

이 검토의 대상은 작성자가 5일 사내 교육을 청강하며 남긴 키워드 메모와 로봇 제어 파이프라인 도식이다. 실제 강의 전체의 범위나 교수의 설명을 평가하지 않는다. 원본에는 주요 키워드가 기록되어 있고, 관계의 정확성이나 설명의 완결성은 아직 확인되지 않았다. 원본 파일은 배포본에 포함하지 않으며, 검토에 필요한 주제와 표현은 아래에 요약했다.

검토 기준은 **휴머노이드의 전체 동작과 수직적 의존성을 이해하는 데 무엇이 필요한가**다. 아래의 중요도·배치는 이 학습 목적에 따른 작성자의 판단이다. 모든 키워드의 개별 논문과 성능을 전수 검증한 결과는 아니다.

## 1. 일자별 기록을 전체 지도에 놓기

일자는 메모의 출처를 구분하기 위한 표기다. 아래는 공식 커리큘럼 전체를 재현한 것도, 이 자료의 권장 학습 순서를 제시한 것도 아니다.

| 원본 | 기록된 주요 묶음 | 새 지도에서의 역할 | 먼저 보완할 연결 |
|---|---|---|---|
| 1일차 | 링크·관절, 기구학, Jacobian, 햅틱스, SLAM | 몸의 표현, 접촉 감각, 상태·지도 추정 | 손의 좌표에서 관절로 이어지는 관계; 햅틱스와 기구학의 구분; 로봇 상태와 지도 |
| 2일차 | 모터·감속기·토크·속도·전력, 구동 회로, 피드백 | 명령을 실제 힘으로 만드는 부분 | 모터→전달계→관절→작업 성능, 명령 모드와 제약 |
| 3일차 | 센서 품질, 힘·토크·촉각, 파지·미끄럼 | 접촉을 측정하고 판단하는 부분 | 측정 품질→접촉 추정→제어·성공 판정 |
| 4일차 | 기구·동역학, 경로·궤적, 추종·상호작용 제어 | 목표에서 구동 명령으로 이어지는 중심 | 순차 단계와 대안의 구별, 휴머노이드 전신·접촉 제약 |
| 5일차 추적 | 단일·다중 물체 추적, 데이터 연관, 평가 | 환경 속 물체의 상태를 이어가는 기능 | 로봇 자신의 상태 추정과 구분, 계획에 필요한 출력 의미 |
| 5일차 SLAM | 센서, FE/BE, 필터·최적화, VIO, 지도 표현 | 로봇 위치·지도 추정 | 보행에 필요한 신체·접촉 추정, 지도 보정과 좌표계 |
| 파이프라인 | 인지·계획·제어의 도식 | 계획·제어 기능을 읽는 출발점 | 구동·환경·피드백, 작업 실행, 복수의 구현 방식 |

센서·구동기 메모는 알고리즘의 주변 지식이 아니다. 상위 알고리즘이 성립하는 조건을 설명할 재료다. 반면 추적·SLAM의 많은 개별 방법 이름은 큰 그림을 이해한 뒤 선택적으로 찾아볼 심화 목록으로 둘 수 있다.

## 2. 휴머노이드 관점에서 보완할 공백

상태 표기는 `기록 있음 / 연결 설명 필요 / 추가 자료 필요 / 제품 확인 필요`다. 하나의 주제에 여러 상태가 적용될 수 있다.

| 주제 | 기록 상태 | 왜 필요한가? | 이번 초안의 처리 |
|---|---|---|---|
| 전체 폐루프와 중첩된 제어 | 기록 있음·연결 설명 필요 | 계획 결과가 실제로 실행되는 과정과 오차의 귀환을 이해 | [전체 흐름](robotics_system_overview.md#system-map)에 연결 |
| Floating base·접촉 모드 | 추가 자료 필요 | 몸체가 고정되지 않은 휴머노이드의 제약을 이해 | [접촉 개념](concepts.md#contact)과 전체 지도에 보충 |
| 균형·보행·전신 조정 | 예시 기록 있음·연결 설명 필요·추가 자료 필요 | 팔과 다리의 목표를 함께 보는 관점 | CoM·ZMP·접촉·WBC의 입구를 추가. 보행 알고리즘 세부는 심화로 남김 |
| 몸체·접촉 상태 추정 | IMU·VIO 기록 있음·연결 설명 필요 | 시각 SLAM과 보행 제어의 상태 추정이 전부 같은 문제는 아님 | [접촉 보조 추정](concepts.md#estimation) 보충 |
| 파지와 전신 동작의 연결 | 힘·촉각 기록 있음·연결 설명 필요 | 손의 목표와 몸의 지지 조건을 함께 이해 | [중심 설명의 집기 상황](robotics_system_overview.md#humanoid)에 통합 |
| 시간·좌표·보정·유효성 | 일부 동기화 기록 있음·연결 설명 필요 | 데이터가 전달되어도 서로 다른 의미로 사용되는 문제를 이해 | [인터페이스 개념](concepts.md#interfaces) 보충 |
| 작업 실행·복구 | 추가 자료 필요·제품 확인 필요 | 경로 성공, 물리적 성공, 보고 성공을 구분 | [집기 흐름](robotics_system_overview.md#integration)에서 단계 진행과 실제 결과를 구분. 복구 정책은 확정하지 않음 |
| 학습된 동작 정책·sim-to-real | 비전 학습 기록 있음·동작 정책은 추가 자료 필요 | 휴머노이드 구현을 명시적인 순차 파이프라인만으로 제한하지 않기 | [대체 구현 관점](robotics_system_overview.md#architectures) 보충 |
| 전력·열·내구·자원 예산 | 모터 전력 등 기록 있음·시스템 연결 필요 | 지속 동작의 한계를 상위 목표와 연결 | 재검토할 축으로 등록. 제품 수치·열 모델은 이번 초안에서 미검증 |
| 안전 기능·보호·고장 대응 | 안전 단정 표현 있음·조건 확인 필요 | 기계 특성과 적용 작업의 안전 판단을 구별 | 아래 교정표에서 일반화 제한. 제품별 기능은 미확인 |
| 시뮬레이션·검증·재현 | 시뮬레이션 예시·벤치마크 기록 있음·연결 필요 | 구성 요소 평가와 전체 작업 평가의 차이를 이해 | 사례에 진단 질문·재현 정보를 제안. 실험은 수행하지 않음 |
| 관측 데이터와 로봇 내부 상태의 연결 | 연결 설명 필요 | 측정·추정·판정의 의미를 구분 | 진단 사례로 연결. 특정 시스템의 구현은 교육의 공백으로 분류하지 않음 |

공백은 서로 독립된 과목 목록이 아니다. 예를 들어 접촉을 이해하면 센서·추정·보행·파지·전신 제어가 함께 연결된다. 따라서 우선순위는 개별 알고리즘 추가보다 **몸체와 접촉 → 폐루프 → 상태·명령의 의미 → 상하위 제약**에 둔다.

## 3. 기존 표현의 의미와 관계 재검토

| 원본 위치·표현 | 검토 결과 | 새 자료에서의 처리와 근거 |
|---|---|---|
| 1·4일차: joint space, Cartesian space, workspace, task space | 구분 필요 | 작업의 표현 공간과 도달 범위, 관절 구성을 구별한다. [MR 2.5](https://modernrobotics.northwestern.edu/nu-gm-book-resource/2-5-task-space-and-workspace/) |
| 1일차: filtering→localization, smoothing→mapping | 일대일 대응으로 읽으면 부정확 | 추정 문제와 추정 방법을 서로 다른 축으로 설명한다. [SLAM 개관](https://arxiv.org/abs/1606.05830) |
| 4일차: 고감속기어→토크제어 불가 | 보편 명제로 사용하지 않음 | 전달계의 특성과 센싱·제어 구성의 조건을 확인한다. 감속비만으로 모든 구현 가능성을 단정하지 않는다. [구동·감속·마찰](https://modernrobotics.northwestern.edu/nu-gm-book-resource/8-9-actuation-gearing-and-friction/) |
| 4일차: 하모닉드라이브+토크 센싱→backdrivable | 서로 다른 성질을 연결한 조건 확인 필요 | 기계적 역구동성과 외력 검출·능동적 응답을 분리한다. 특정 제품의 실제 특성은 미확인. 같은 [구동 설명](https://modernrobotics.northwestern.edu/nu-gm-book-resource/8-9-actuation-gearing-and-friction/)에서 동적 특성을 먼저 확인 |
| 4일차: 역구동 불가→충돌 검출 불가→사람과 공존 불가; 협동로봇→공존 가능 | 안전 판단으로 일반화하지 않음 | 적용 작업·도구·환경·보호 기능을 함께 평가해야 한다. [OSHA 로봇 적용 안전 설명](https://www.osha.gov/otm/section-4-safety-hazards/chapter-4). 미국 산업용 로봇 문맥의 자료이며 국내 휴머노이드 인증 판단으로 전용하지 않음 |
| 4일차: 손목 F/T 센서 외 접촉 검출 불가 | 해당 구성의 가정 확인 필요 | 다른 센서·추정기를 포함한 전체 구성 정보가 없으므로 일반 명제로 채택하지 않음. 힘 피드백 구성의 차이는 [MR 11.5](https://modernrobotics.northwestern.edu/nu-gm-book-resource/11-5-force-control/) 참고 |
| 2일차: PWM은 속도 제어, Control=current | 제목을 등식으로 읽지 않음 | 회로 구동 방식, 제어할 물리량, 피드백 루프를 구분한다. [제어 블록 구성](https://modernrobotics.northwestern.edu/nu-gm-book-resource/11-1-control-system-overview/) |
| 5일차 추적과 4일차 Tracking control | 같은 단어지만 역할이 다름 | 물체 상태를 이어가는 추적과 기준 운동을 따르는 제어를 분리한다. [SORT](https://arxiv.org/abs/1602.00763), [제어 개요](https://modernrobotics.northwestern.edu/nu-gm-book-resource/11-1-control-system-overview/) |
| 1일차: 인간의 감각 반응속도 순위·수용기 표기 | 이번 초안에서 미검증 | 로봇 센서의 시간 성능이나 제어 주기로 옮겨 사용하지 않음. 인간 감각 생리의 세부 내용은 심화 보류 |
| 4일차의 제조사별 제어 방식·구체적 성능 주장 | 제품·버전 미확인 | 제품 설명으로 재사용하지 않음. 해당 매뉴얼과 조건을 확보할 때 검토 |

이 표는 교정이 필요한 위치를 추적하기 위한 것이며, 원본 메모 자체는 수정하지 않았다.

## 4. RobotControlPipeline의 연결을 어떻게 바꾸었나?

검토에 사용한 도식은 이미지를 Markdown으로 전환한 자료다. 이미지 전사의 충실도는 이 검토에서 판정하지 않았다. 아래는 Markdown에 표현된 관계를 요약하고 해석한 것이다.

| 원본에서 읽히는 구조 | 초안의 해석 |
|---|---|
| Perception에 SLAM과 CAD/map을 함께 배치 | 추정 기능과 사전 환경 모델을 구분한다. 둘 다 계획에 쓰일 수 있지만 같은 종류의 처리 단계는 아니다. |
| Route finding → Path optimization → interpolation → generation | 가능한 분해 예로 읽는다. 모든 방법이 이 순서의 모든 단계를 거치는 것은 아니다. [계획 개요](https://modernrobotics.northwestern.edu/nu-gm-book-resource/10-1-overview-of-motion-planning/) |
| OCP·TrajOpt·CI-TrajOpt·NLP·MPC를 묶은 띠 | 문제 형식·방법·특정 알고리즘이 섞여 있다. “최적화”라는 하나의 실행 단계로 만들지 않는다. CI-TrajOpt 약어의 정확한 지칭은 원 강의 근거 확보 전까지 미확인으로 둔다. [최적화 개요](https://underactuated.mit.edu/trajopt.html) |
| Interaction control → Tracking control | 계층화 가능한 구성 예로 읽는다. 모든 상호작용 제어가 반드시 별도 추종 블록을 호출한다고 고정하지 않는다. [교재 11장](https://hades.mech.northwestern.edu/images/b/b2/MR-2up.pdf) |
| 최적화 띠 → Path following | 최적화가 경로 추종의 필수 선행 단계라는 뜻으로 확대하지 않는다. 원 연결의 의도는 미확인으로 남긴다. |
| Reactive control에 bug·APF·E2E | 반응형 접근과 학습된 입력→출력 구성을 같은 분류 축으로 단정하지 않는다. E2E가 포함하는 기능 범위는 논문·구현마다 확인한다. |
| 구동·환경·센서 귀환 생략 | [전체 지도](robotics_system_overview.md#system-map)에서는 피드백과 실제 구동을 추가해 기능의 의미를 연결한다. |

## 5. 키워드 보존과 심화 범위

원본의 알고리즘 이름은 없애지 않는다. 이번 초안에서 우선 설명하는 것은 문제·입출력·관계다. 예를 들어 MeanShift부터 MASA까지의 계보, 모든 SLAM 시스템의 비교, 모터 종류별 상세 선정표를 전부 작성한 상태는 아니다.

| 원본 묶음 | 이번 초안의 읽기 위치 | 남은 심화·확인 |
|---|---|---|
| FK·IK·Jacobian·singularity·manipulability | [몸의 표현](concepts.md#geometry) | 조작성·감쇠 의사역행렬의 상세 조건 |
| DC·BLDC·stepper·AC·QDD·구동 회로 | [구동과 센싱](concepts.md#hardware) | 모터 분류·제품별 구동 방식과 성능 |
| 센서 정적·동적 특성, 촉각 변환 원리, 햅틱스 | [센싱 조건](concepts.md#hardware) | 촉각 센서 구현과 인간 감각의 별도 설명 |
| 탐색·최적화·보간·TOPP·MoveIt | [계획](concepts.md#planning) | 개별 알고리즘과 도구의 기능·버전 |
| PD·FL·PBC·LQR·SMC·adaptive·MPC | [제어](concepts.md#control) | 각 방법의 가정·안정성·trade-off |
| VOT·MOT·3D tracking·SAM 계열 | [추정](concepts.md#estimation) | 물체 상태의 표현과 벤치마크별 평가 조건 |
| SLAM FE/BE·VIO·neural mapping·SfM | [추정](concepts.md#estimation) | 지도 표현별 기능, 온라인 위치 추정과 재구성의 차이 |

`RPM`은 주변 RRT 목록을 보면 PRM의 오기일 가능성이 있지만 확정하지 않는다. `Rouge phenomenon` 등도 원본 표기를 보존하고 사용하려는 시점에 확인한다. 이름만으로 특정 논문을 잘못 연결하지 않기 위해 이번 초안의 기술 근거로 쓰지 않았다.
