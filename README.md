# 휴머노이드 이해하기

<a id="audience"></a>
## 누구를 위한 자료인가?

SW 분야에 전문성이 있고, 로봇 전문가와 협업하기 위해 휴머노이드를 이해하려는 독자를 대상으로 한다. 물리학(physics)·기구학(kinematics)·동역학(dynamics)은 처음 접한다고 가정한다. 함수·상태·모델처럼 익숙한 개념을 설명의 발판으로 삼고, 벡터·미분·확률 표현은 필요한 의미를 짚으며 사용한다. 특정 DS·딥러닝·LLM 전공 지식은 필수로 요구하지 않는다.

## 무엇을 이해하려는가?

휴머노이드의 주요 기술이 어떤 문제를 해결하고, 서로 어떤 정보와 물리적 조건에 의존하는지 이해하는 것이 목표다. 작업 목표가 실제 움직임으로 이어지는 폐루프(closed loop)와, 센서(sensor)·구동기(actuator) 등의 한계가 상위 동작에 미치는 영향을 연결한다. 이를 바탕으로 전문가의 설명을 읽고 입력·출력·가정·제약에 관해 질문할 수 있는 수준을 지향한다.

설명은 구체적인 물리 현상에서 시작해 용어·변수·단위와 필요한 수식, 로봇에서의 쓰임으로 이어가는 것을 원칙으로 한다. 주요 개념은 각 문서의 첫 설명에서 **한글**(영문, 약어)로 병기하고, 이후에는 한글이나 약어를 사용한다. 필요한 기초에는 설명을 할애하고, 개별 알고리즘의 유도·구현은 심화 자료로 연결한다. 휴머노이드의 원리와 기능 간 관계를 이해하는 데 범위를 둔다.

이 자료는 작성자가 **5일 사내 로봇 교육을 청강하며 남긴 키워드 메모를 정리하는 과정**에서 시작됐다. 이후 교육 수강생도 기존 교육의 구성과 일자별 주제를 살펴보고, 배운 용어를 전체 동작과 연결해 복습할 수 있도록 [교육 구성과 일자별 읽기 안내](learning_path.md)를 함께 제공한다.

교육에서 다룬 주제는 당시 메모를 기준으로 소개하고, 아래 오버뷰는 여러 분야의 관계를 이해하도록 휴머노이드의 집기 상황으로 재구성한 설명이다. 메모를 바탕으로 보충한 내용과 원래 교육 기록의 범위는 구분한다.

## 읽기 시작

교육 구성을 먼저 확인하려면 [교육 구성과 일자별 읽기 안내](learning_path.md)를 본다. 전체 원리를 먼저 이해하려면 아래 글부터 읽으면 된다.

**[휴머노이드는 어떻게 원하는 동작을 만드는가?](robotics_system_overview.md)**

위 글은 전체 원리를 설명하는 중심 문서다. 도입부의 [전체 연결도](robotics_system_overview.md#system-map)에서 목표·계획·제어·구동·센싱·추정이 주고받는 정보와 피드백을 보고, 각 절의 설명을 읽는다. 물체를 보고, 손을 뻗고, 잡아 드는 상황을 따라가며 좌표계·기구학·힘과 토크·피드백·접촉·균형을 설명한다. 필요한 물리 기초와 구체적인 예를 본문에 포함했으므로 개념 문서를 먼저 공부할 필요는 없다. 한 번에 읽기 길면 1–3절에서 위치·움직임·구동의 관계를 읽고, 4–7절에서 피드백·접촉·전신 동작으로 이어가면 된다.

용어가 낯설 때는 [분야별 개념](concepts.md)을 찾아본다. [관측된 현상을 해석하는 예](platform_robot_walkthrough.md)는 선택해서 읽을 보충 자료다.

원본 교육 키워드의 대응·교정·공백은 [검토 기록](curriculum_coverage_and_gaps.md)에, 기술적 근거는 [출처 목록](references.md)에 보존했다. 처음부터 함께 읽을 필요는 없다.

## 순수 SW 배경에서 보충할 분야

아래는 먼저 모두 이수해야 하는 선수과목이 아니라, 로봇 설명에서 막힐 때 참고할 지도다. 이미 익숙한 분야는 건너뛰고, 중심 글을 읽다가 필요한 개념만 보충하면 된다. 각 분야의 전문 구현보다 **무엇을 설명하는지, 어떤 한계가 다른 요소에 영향을 주는지**를 이해하는 데 집중한다.

| 분야 | 이 자료에서 알아둘 내용과 연결 |
|---|---|
| 물리학·동역학 | 힘(force)·토크(torque)·질량(mass)·관성(inertia)·마찰(friction)이 움직임을 어떻게 바꾸는가. 원하는 동작이 실제로 가능한지, 왜 부하와 접촉 조건이 중요한지 이해한다. |
| 공간 표현·기구학 | 좌표계(coordinate frame)·위치(position)·방향(orientation)과 관절 움직임의 관계. 센서가 본 위치, 손의 목표 위치, 관절의 값을 연결한다. |
| 제어 이론(control theory) | 피드백(feedback)·오차(error)·안정성(stability)·응답(response)의 의미. 명령 한 번으로 끝나지 않고 측정과 보정을 반복하는 이유, 진동이나 지연이 문제가 되는 이유를 이해한다. |
| 센싱(sensing)·계측(measurement)·신호처리(signal processing) | 측정 오차(measurement error)·보정(calibration)·잡음(noise)·샘플링(sampling)·필터(filter)의 의미. 측정값은 현실 그 자체가 아니며, 정밀도와 지연이 추정·제어에 영향을 준다는 점을 이해한다. |
| 상태 추정(state estimation)·시스템 식별(system identification) | 센서와 모델로 직접 알 수 없는 상태를 추정하고, 실험 데이터로 모델의 특성을 알아내는 분야. 현재 상태를 알아내는 일과 모델을 맞추는 일을 구분한다. |
| 전기·전자·구동(actuation) | 전압(voltage)·전류(current)·전력(power), 모터(motor)와 모터 드라이버(motor driver)의 역할. SW 명령이 물리적 출력으로 이어지며 전력·발열·출력 한계의 영향을 받는다는 점을 이해한다. |
| 기계 요소(machine elements)·전달계(transmission) | 감속기(speed reducer)·전달기구·유격(backlash)·탄성(elasticity)의 의미. 모터의 움직임과 힘이 관절에 그대로 전달되는 것은 아니며, 기계 구조가 정밀도와 응답에 영향을 준다는 점을 이해한다. |
| 임베디드 시스템(embedded system)·실시간 시스템(real-time system)·RTOS | 제어 주기(control period)·마감시간(deadline)·지터(jitter, 실행 시점의 흔들림), 인터럽트(interrupt)·스케줄링(scheduling)·우선순위(priority)의 의미. 계산 결과뿐 아니라 언제 측정하고 실행했는지도 제어에 중요하다는 점을 이해한다. |

실시간 운영체제(real-time operating system, RTOS)는 정해진 시간 요구를 만족하도록 실행을 관리하는 기반이다. ‘평균적으로 빠른 OS’라는 뜻은 아니며, RTOS를 쓴다는 사실만으로 시스템 전체의 시간 요구가 보장되지는 않는다. 여기서는 역할과 시간 제약을 이해하면 충분하다. 특정 RTOS 채택이나 로봇 내부의 실행 위치는 가정하지 않는다. [실시간 개념](https://design.ros2.org/articles/realtime_background.html), [스케줄링의 구체적 예: Zephyr](https://docs.zephyrproject.org/latest/kernel/services/scheduling/index.html).

위 목록은 기초를 보충할 방향이지 로봇 기술 전체의 분류가 아니다. SLAM·동작 계획(motion planning)·보행(walking)·파지(grasping) 등은 중심 글에서 이 기초가 실제 문제에 쓰이는 맥락으로 만난다.

## 세부 내용은 어디까지 읽는가?

분야별 내용을 모두 채우지는 않는다. **설명이 없으면 본문의 인과관계를 이해하기 어려운 개념만 본문에 포함**하고, 나머지는 다음처럼 나눈다.

- 본문: 필요한 위치에서 개념의 뜻과 로봇 예를 짧게 설명한다. 수식은 의미 이해에 도움이 될 때만 쓰며, 변수와 단위를 함께 설명한다.
- 선택 보충: 더 설명이 필요한 개념은 [분야별 개념](concepts.md)에 짧게 보충하고 해당 위치에서 연결한다. 정의만 나열하지 않고 예 하나와 다른 요소에 미치는 영향을 다룬다. 목록 전체를 미리 상세화하지 않는다.
- 심화: 알고리즘 유도·구현, 회로 설계, RTOS 커널 내부나 제품별 설정은 필요할 때 외부 자료로 찾아간다. [출처 목록](references.md)은 근거를 확인하는 용도이며 필독 목록이 아니다.

예를 들어 RTOS는 ‘같은 계산 결과라도 늦게 도착하면 제어에 문제가 될 수 있다’는 점과 실행 순서·시간을 관리하는 역할을 이해하는 데서 시작한다. 직접 태스크를 설계하거나 지연 문제를 분석할 필요가 생길 때 세부 스케줄링 기법을 찾아보면 된다.

한 개념이 **왜 필요한지, 무엇과 연결되는지, 어떤 제약이 있는지** 자기 말로 설명할 수 있다면 우선 다음으로 넘어가도 된다. 이는 시험이나 수료 조건이 아니라, 깊이를 조절하기 위한 읽기 기준이다.
